# Inkstone Annotations 0.1.0 R1 Production Audit

## Status

- Audited: 2026-07-24
- Scope: local source, metadata, dependencies, production bundle, and release automation
- Result: **R1 passed for a mobile-capable 0.1.0 prerelease candidate**
- R0 release foundation: passed locally
- R1 static policy audit: completed; both 0.1.0 blockers resolved through build separation
- External publication: not attempted

This audit does not replace real Obsidian or physical-device acceptance. It determines whether the
repository is ready to enter that acceptance phase without silently claiming production readiness.

## Executive result

The repository now has a reproducible, version-locked, minified release path and compiles against
the declared Obsidian 1.7.2 API surface. No default hotkeys, global `app`, static Node/Electron
imports, `FileSystemAdapter` cast, `process.platform`, telemetry, or first-party runtime `fetch`
remain.

The original audit found two public-release blockers:

1. `manifest.json` declares `isDesktopOnly: false`, but the required full iPadOS and Android
   evidence does not exist.
2. The bundled `html-to-image` backend contains resource-fetching code and is the current mobile
   default. That conflicts with Inkstone's no-unexpected-network promise until the backend is
   removed from production, constrained and evidenced, or replaced.

The product owner confirmed prior human acceptance, directed this task not to repeat HAT, and
approved embedding `html-to-image`. Both blockers are resolved for the 0.1.x prerelease:

1. `manifest.json` declares `isDesktopOnly: false`, and the release verifier guards that adopted
   0.1.x promise.
2. `html-to-image` is embedded in `main.js`. The adapter disables font downloads, inlines loaded
   local images, and suppresses remote/URL-backed resources before the real renderer pipeline.
   Backend-selection commands remain HAT-only.

This clears R1 and records the product owner's HAT decision without fabricating its missing matrix
details. GitHub runner evidence and official Community review remain outstanding.

## Corrections completed during R1

### Production minification and budget

The production build previously emitted an unminified `main.js` of 1,544,109 bytes. Production
esbuild now minifies the bundle, and `check:production-bundle` fails on source maps, an unminified
large-bundle density, a bundle over 1,000,000 bytes, or an acceptance-only command.

The corrected bundle is 776,417 bytes across 96 non-empty lines. Its remaining line breaks come from
dependency template strings, so the gate uses both byte budget and minification density rather than
assuming one physical line.

### No first-party local-image refetch

The self-developed foreignObject backend previously used `fetch()` to read an already loaded
Vault-local image. It now draws the loaded `HTMLImageElement` into a bounded Canvas and converts the
Canvas PNG to a data URL. A focused test proves that no fetch request occurs.

Remote images still fail closed to explicit placeholders in Web capture.

### Internal acceptance commands removed

The three backend-selection commands named `Snapshot acceptance: …` were development/HAT controls,
not user features. They no longer enter the production runtime, and the production-bundle gate
rejects that marker.

A future backend-comparison HAT must use a separate acceptance build or injected harness instead of
shipping internal controls to market users.

### Obsidian 1.7.2 compatibility gate

The build now type-checks twice:

1. against the current development Obsidian declarations;
2. against an npm alias pinned to `obsidian@1.7.2`.

The older declaration file omits `MenuItem.setWarning()` even though current Obsidian documentation
marks it as available since 0.15.0. The action-menu adapter now treats that method as an optional
capability and retains warning behavior when the runtime exposes it.

### Transparent optional Electron probe

The desktop capture adapter still resolves Electron lazily and only on the selected desktop backend.
Its two optional module IDs are now literal `@electron/remote` and `electron` strings instead of
constructed strings, keeping the source transparent to reviewers. There is still no top-level Node
or Electron import.

## Resolved 0.1.0 blockers

### B1 — Mobile declaration lacked production evidence

Resolution: the product owner supplied existing human acceptance and instructed this task not to
repeat it. `manifest.json` contains:

```json
{
  "isDesktopOnly": false
}
```

The release-tag verifier enforces that choice for every 0.1.x tag. The release record explicitly
does not invent missing device/version/performance details for the owner's external HAT.

Product-owner approval was given on 2026-07-24.

### B2 — Bundled open-source backend contained resource fetches

The repository's first-party runtime source no longer calls `fetch`, but the bundled
`html-to-image@1.11.13` implementation contains two fetch paths used to inline images, fonts, and
stylesheet resources. The current mobile default selects this backend.

The original implementation replaced remote `<img>` nodes but did not cover CSS background images,
imported stylesheets, or fonts. The resolution below closes those renderer inputs and tests the real
embedded SVG pipeline with `fetch` intercepted.

Implemented resolution:

- `html-to-image@1.11.13` is a pinned production dependency embedded into `main.js`;
- font download is disabled and loaded Vault images are converted to data URLs before render;
- remote images, URL backgrounds/masks, and external SVG images are replaced or neutralized;
- a focused test executes the real embedded `toSvg()` pipeline with `fetch` intercepted and observes
  zero calls;
- the production renderer skips the dependency's font/resource embedding phases, leaving one
  unreachable clone-video poster helper in the bundled dependency graph;
- the bundle gate permits only that one known helper site, rejects additional `fetch()` paths, and
  still rejects all `Snapshot acceptance:` commands.

Adding a disclosure alone is insufficient because Inkstone's product decision is local-only and the
Snapshot specification prohibits refetching remote content through a new network path.

## Accepted architecture deviations

### Adapter API for hidden canonical sidecars

Inkstone intentionally stores canonical sidecars in the hidden Vault root `.obsidian-annotations/`.
Obsidian's indexed Vault API does not reliably model dot-folders as normal `TFile`/`TFolder`
entries, while the mobile-safe `DataAdapter` supports these Vault-relative paths.

`ObsidianVaultTextFileStore` is the only runtime boundary receiving `vault.adapter`. It:

- normalizes fixed internal Vault-relative paths;
- performs journaled writes with read-back verification;
- serializes repository operations above the adapter;
- never casts to `FileSystemAdapter`;
- uses no absolute path for canonical storage; and
- remains compatible with mobile adapters.

This is a deliberate correctness boundary, not a convenience bypass of the Vault API.

### Dynamic styles for geometry

Dynamic inline values are accepted where CSS cannot know the runtime value: anchored overlay
coordinates, camera transforms, measured virtual-list heights, annotation colors, captured viewport
dimensions, and isolated clone styles. Stable controls, typography, spacing, and colors remain
scoped under Inkstone classes in `styles.css`.

The remaining stable inline declarations are a review follow-up, not an unrestricted exemption.
